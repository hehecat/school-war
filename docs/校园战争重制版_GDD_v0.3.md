## 1. 项目概述

**一句话**：四个校园社团在方格地图上抢地盘，占地越多出兵越快但边际收益递减，最后一统校园的多人实时策略小游戏。

| 项目 | 内容 |
|---|---|
| 类型 | 轻量实时策略（RTS-lite）/ 方格占领 |
| 平台 | Web 浏览器，桌面优先，兼容手机触屏 |
| 技术 | TypeScript、Three.js、WebSocket |
| 人数 | 1-4 人，空位由 AI 补位 |
| 单局时长 | 目标 5-8 分钟，硬上限 8 分钟 |
| 目标玩家 | 怀旧老玩家 + 轻竞技休闲玩家 |

**版权边界**：玩法概念借鉴 Flash 小游戏《校园战争》，**美术、名称、音频、文本全部原创，不使用任何原作素材**。

## 2. 设计支柱

1. **一眼看懂**：规则一句话讲清，30 秒上手。
2. **抢地盘就是一切**：任何系统都必须回答「它让玩家对格子做了什么新决策」。
3. **每局都有翻盘，且翻盘可以准备**：靠预警后的提前布局，不靠随机补偿。
4. **轻量快速**：首屏 < 3 MB，一局 ≤ 8 分钟。
5. **胜负靠决策，不靠开局运气**：PvP 中所有随机性必须公开、可反制、双方同时知情。

## 3. 核心循环

| 层 | 内容 |
|---|---|
| **秒级（0-30s）** | 选己方格 → 拖向目标格 → 选投入比例 → 兵团移动 → 交战 → **决定增援 / 撤退 / 硬吃** |
| **分钟级（5-8min）** | 扩张 → 争夺关键格 → 应对预警事件 → 技能 / 道具 / 手牌 → 争夺广播室翻盘窗口 |
| **局间** | 战绩与归因 → 社团声望 → 解锁外观、涂鸦、更多「校园传说」 |

## 4. 核心规则

### 4.1 地图与格子

- MVP 地图 16×16 = 256 格，四邻相连。障碍格不可通行、不可占领。
- 每格属性：归属、驻军数、类型、单格兵力上限（默认 20）、连通状态。

### 4.2 出兵 ★修订 A3 / B2 / B3

**档位按地图规模自适应**：设 `S = 可占格数 ÷ 玩家数`。

| 地图 | 可占格数 | S |
|---|---|---|
| 主教学区 16×16 | ≈ 220 | **55** |
| 宿舍楼 192 格 | ≈ 180 | **45** |

**边际档位**（格子按「单格基础贡献 = 类型系数 × 连通系数」降序排列后的第 i 位）：

| 位次 i | 档位系数 |
|---|---|
| i ≤ 0.5 S | ×1.00 |
| 0.5 S < i ≤ 1.0 S | ×0.60 |
| 1.0 S < i ≤ 1.5 S | ×0.35 |
| i > 1.5 S | ×0.15 |

```
每格每秒产出 = 0.5 × 社团出兵系数 × 档位系数(i) × 格子类型系数 × 连通系数
```

**为什么按贡献降序排位**：这样方块格（×2）、连通格天然落在高档位，边际的孤立/断补给格落在 ×0.15 档。结果是**抢一格好地 > 抢三格废地**，与「地盘是形状不是数量」一致，而且规格唯一、无歧义。

> 实现兜底：若排序逻辑对玩家心智负担过大，可退化为**全体统一系数**的平滑函数 `f(N) = 1 / (1 + max(0, N - 0.5S) / S)`，单调且无档位断点。二者需在 M0 阶段各跑一次模拟对比。

**总产出对照（S=55，不含类型与连通系数）**：

| 占地 N | v0.1 线性公式 | **v0.3 边际递减** |
|---|---|---|
| 9 格（开局） | 4.9 兵/秒 | 4.5 兵/秒 |
| 27 格 | 17.2 | 13.5 |
| **40 格** | **28.0** | **17.4** |
| 55 格（人均） | 42.6 | 21.9 |
| **80 格** | **72.0** | **26.3** |
| 110 格 | 115.5 | 28.8 |
| 150 格 | 187.5 | 31.7 |

**主对比（40 → 80 格，占全图 15% → 31%，是实际对局的主要区间）**：
- v0.1：2.57 倍
- v0.3：**1.51 倍**

**rationale**：前 0.5S 格完全保留正反馈爽感（开局扩张回报明确），之后急剧压缩。领先者仍有净收益但不足以锁死，第二名守得住、也必须主动出击。

### 4.3 派兵与移动

- 选中己方格拖向目标格，投入比例 **25% / 50% / 100%** 三档（默认 50%）。
- 基础速度 1 格/秒 × 社团速度系数。

### 4.4 战斗结算 ★修订 A1（本版最大改动）

**v0.2 的错误**：沿用 v0.1 的 `损失 = 敌兵数 × 攻 ÷ 血`，缺速率常数。实际每个兵每 0.5 秒就杀死「攻÷血」个敌人，20v20 一轮同归于尽，TTK 仅 0.5-2.5 秒 —— 撤退与增援都无从操作。

#### v0.3 模型：锁定交换率

**接触瞬间锁定双方交换率**（之后不再随兵力变化，除非发生增援合并）：

```
rA = N_B × atk_B × k / hp_A      （A 每 0.5s 损失的兵数）
rB = N_A × atk_A × k / hp_B
```

- 每 0.5 秒（10 tick）双方各扣 rA / rB，定点数精度 0.01。
- 一方 ≤ 0 即结束。若同一轮双方同时 ≤ 0 → **同归于尽**。
- **k = 0.15** `[PLACEHOLDER]`

#### 为什么是「锁定」而不是「按当前兵力」

按当前兵力结算会退化成指数衰减，**永远打不完**（小兵力时损失趋近 0，陷入僵局）。锁定交换率让战斗时长可预测、可单测，也让增援有明确意义。

#### TTK 与结果（k = 0.15，同属性，atk = hp = 1）

| 对抗 | 时长 | 进攻方剩余 | 说明 |
|---|---|---|---|
| 20 vs 20 | **3.3 s** | 0（同归于尽） | 强攻等价交换 |
| 20 vs 18 | 3.0 s | 3.8 | 险胜，代价极高 |
| 20 vs 15 | 2.5 s | 8.8 | 优势进攻 |
| 20 vs 10 | 1.7 s | 15.0 | 压倒性 |

**均匀对抗的 TTK = 0.5 / k 秒**（与兵力无关，是 k 的直接函数）。k=0.15 → 3.3 秒，落在「看得清局势、来得及点撤退」的窗口内。

#### 闭式解（供单元测试与平衡推演，推导见附录 A）

```
进攻方 A 胜 ⇔  N_A² × atk_A × hp_A  >  N_B² × atk_B × hp_B
A 幸存兵力  =  N_A − N_B² × atk_B × hp_B / (N_A × atk_A × hp_A)
```

**这修正了 v0.2 的一个说法**：v0.2 称「兰彻斯特平方律下判据是攻×血」，该说法只在**等兵力**时成立。完整判据是 **N² × 攻 × 血**。

#### 由闭式解派生的三条设计结论

1. **增援是最强的战斗操作**：合并新兵团后**重新锁定交换率**。20 vs 20 打到一半时投入 10 兵，交换率立刻翻盘。这让「要不要再派一队」成为战斗中的核心决策 —— 这正是 v0.2 想用撤退填而没填上的「决策真空」。
2. **撤退可行**：3.3 秒的窗口内，第 1-2 秒即可判断胜负并撤出，损失约 30%-50% `[PLACEHOLDER]`。
3. **集中兵力有超额回报**：判据是 N²，40 打 20 远比两个 20 打 20 划算。这与单格上限 20 形成对冲 —— 上限越低，越接近线性，绿的出兵优势越难兑现（见 6.2）。

### 4.5 占领与同归于尽 ★修订 A4

- 击败守军**且有幸存兵力** → 格子易主，幸存兵力成为新驻军。
- **同归于尽 → 格子归防守方**，驻军归零。
- **设计后果（intended）**：同归于尽后防守方格空虚，进攻方**第二波**可以零代价拿下。这创造了「两波进攻」的战术 —— 第一波换血，第二波收割。这是从规则里自然长出来的，不是额外机制。

### 4.6 胜负与流亡 ★修订 B6

**本作不存在「淘汰」**。失去全部格子与全部兵团的玩家进入**流亡**状态：

- 流亡期间可在任意中立格重建（或由下一支产出的兵团自动占领最近中立格）`[PLACEHOLDER]`。
- 流亡者仍计入排名（0 格）。

| 条件 | 内容 |
|---|---|
| **主胜利** | 时间到（**480 秒**）占格最多者获胜 |
| **速胜 A** | 其余三家**同时处于流亡状态并保持 20 秒**（给流亡者重建窗口） |
| **速胜 B** | 占全图 ≥60% 并保持 20 秒 `[PLACEHOLDER]` |
| **Mercy** | t=420s 时若第一名格数 ≥ 第二名 ×2，提前结算 |

## 5. 经济系统：Sources & Sinks ★修订 B1

| Sources | Sinks |
|---|---|
| 格子产出（受递减约束） | 战斗阵亡（唯一的持续 sink） |

| 食堂开饭事件 | 断补给 ×0.5（效率 sink） |
| 红桃格回血 | 教导主任没收（事件级） |

### 三套上限的分工（本版明确）

| 约束 | 类型 | 作用 | 是否应按平衡调 |
|---|---|---|---|
| **边际递减** | 经济 | 管**流入速率**，压住大地盘的产能 | ✅ 是 |
| **单格上限 20** | 战术 | 管**集中度**，决定平方律能兑现多少（绿的关键变量） | ✅ 是 |
| **战斗阵亡** | 经济 | 唯一的持续**流出** | ✅ 是 |
| **全局 1200 / 社团** | **技术** | 纯渲染与同步天花板，**正常对局不应触及** | ❌ 否 |

**rationale**：v0.2 把全局 400 当成平衡手段，但领先者 30/秒只要 13 秒就填满，它会先于其他两套生效，使递减和单格上限双双失效 —— 等于用第三个阀门把前两个关死了。现在把它抬到 1200 并明确定性为技术天花板：**一旦触及，说明前面三套约束失效，是失败信号（见 21 节信号 B），而不是一个需要调参的平衡项。**

### 6.2 绿的强度：v0.2 判定作废，改为模拟决定 ★修订 A2

**v0.2 的错误**：用「攻 × 血」排强弱，漏掉了兵数 N。按 4.4 的闭式解，完整判据是 **N² × 攻 × 血**，而 N 由出兵速度决定。

| 口径 | 紫 | 黄 | 绿 | 黑 |
|---|---|---|---|---|
| 攻 × 血（等兵力单挑） | 1.50 | 1.60 | 0.90 | 1.32 |
| 攻 × 血 × 出兵（**完全分散**：单格上限硬约束，兵力无法集中） | 1.50 | 1.44 | **1.44** | 1.59 |
| 攻 × 血 × 出兵²（**完全集中**：单格上限不约束） | 1.50 | 1.30 | **2.30** | 1.90 |

**结论**：绿的真实强度落在 **[1.44, 2.30]** 区间内，**具体落点由「单格兵力上限 20 是否约束得住它」决定**：

- 若战斗以「格对格」的分散形式发生 → 上限硬约束，绿 ≈ 1.44，与黄持平，且它 0.9 的攻×血是真劣势。
- 若战斗以「集中主力决战」的形式发生 → 上限不约束，绿 ≈ 2.30，是**全场最强**。

**处置**：
1. **撤销** v0.2 给绿的「每格上限 ×1.5」——在该区间下这是**矫枉过正**，很可能把最强的一家推得更强。
2. 绿的被动**留空，由 M0 模拟结果决定**。模拟需统计「平均每场战斗的兵力集中度」，这是决定绿强弱的唯一变量。
3. 失败信号 D 改为**双向**：绿胜率 < 40% 或 > 60% 都需处理。

**这一条同时说明了一个更一般的教训**：单格上限 20 不只是个防堆兵的数字，它是**调节平方律兑现程度的总阀门**。后续所有社团平衡，都应优先调它，而不是调攻防血出兵。

### 8.1 MVP 地图：主教学区（16×16）

### 8.2 多层地图：宿舍楼 ★修订 B5

| 项 | 设计 |
|---|---|
| **结构** | 3 层，每层 8×8 = 64 可通行格，共 192 格 |
| **起始** | 每家在 1F 一角，3×3 起始区 |
| **楼梯** | 每层 4 个，位于该层四边中点内侧，层间垂直对齐 → 对四家等距 |
| **咽喉** | 楼梯是唯一跨层连接 → 占领楼梯 = 控制跨层补给线 |
| **翻墙格** | 4 个，对称分布，单向通行（A→B，不可 B→A） |
| **寻路** | **有向图 BFS / Dijkstra** |

#### 单向边的正确性保证（替换 v0.2 的错误方案）

v0.2 的「停留 5 秒才能再动」和「每 30 秒翻转方向」都已被否定：

- 「停留 5 秒」**解决不了被困** —— 被困是有向图连通性问题，不是单位行为问题。
- 「每 30 秒翻转方向」**会让在途兵团路径失效**，且违背支柱 3（翻盘可以准备）—— 玩家无法预判 30 秒后通路方向。
- 「原路返回」**与单向语义直接矛盾**。

**替代方案（编辑期 + 运行时双重校验）**：

1. **编辑期强连通校验**：地图导出的有向图必须通过强连通性检查（Tarjan）。任一单向边的存在不得破坏任意两格之间的双向可达性。校验不通过则地图不可发布。
2. **单向边成对设计**：设计上要求每条 A→B 的翻墙格附近，存在另一条 B→A 的路径（可以明显更长）。单向的意义是**制造捷径与绕行的时间差**，不是制造死路。
3. **运行时路径校验**：兵团进入单向格前，校验目标侧是否存在回到己方连通区的路径；若无，UI 直接禁止该操作并提示。
4. **分层独立校验**：每一层自身必须是强连通的，不能依赖其他层作为回程。

#### 可读性

层切换按钮 + 非当前层半透明 X 光 + 单位跨层时显示上下箭头 + 小地图按层分栏。

#### 平衡红线

三层面积必须相等；楼梯对四家等距；**不得出现某家能独占一层的地形**。

**开发建议**：M1 阶段先做 **2 层、无翻墙格**的技术预研，验证通过再上完整 3 层。

## 9. 事件

每局随机抽取 **2 个事件**（MVP 池 3 个），触发前 **10 秒预警 + 倒计时**。

| 事件 | 效果 | 目的 |
|---|---|---|
| **教导主任巡视** | 手电扫过一片区域，范围内兵团被没收 30% | **确定性地点名当前占格最多的社团**（非随机） |
| **消防演习** | 所有兵团强制撤回最近己方格，出兵暂停 10s，空出的格变中立，先到先得 | 翻盘窗口 |
| **食堂开饭** | 全员 +10 兵/格（受上限约束），战斗暂停 10s | 喘息与外交窗口 |

**后续池**：停电、转学生、校霸出没、流感、谣言、大扫除、家长会、校庆烟火 + **广播站**（t=240s 中心刷出，占领读条 6s 后**二选一**：己方 15s 移速 +30% / 敌方 10s 移速 -30%）。

**事件红线**：
1. 事件**不得消灭地盘**，只能没收兵力。
2. 事件必须**可反制**：预警期内占领某格可减免或转移 `[PLACEHOLDER]`。

## 11. 扑克牌系统 ★修订 B4

v0.2 存在三处逻辑矛盾：手牌上限 3 却写「4 张清一色」（不可达）、「凑齐 2 张立刻生效」使 3/4 张档位永远到不了、反复夺回同一花色格可无限刷牌。

### v0.3 规则

| 项 | 规则 |
|---|---|
| **手牌上限** | **4 张**。超出时挤掉最旧的一张 |
| **抽牌** | 占领花色格抽对应花色牌。**每个花色格对每个社团只抽一次** —— 同一格被同一社团反复夺回不再抽牌 |
| **兑现** | **手动打出并消耗**：2 张同花色 → 10s 增益；3 张同花色 → 15s 更强增益；4 张清一色 → 20s（彩蛋） |
| **手牌公开** | 四家手牌在 HUD 上全部可见 |
| **效果** | 红桃：全格回血 / 黑桃：全格上限 +5 / 方块：出兵 ×1.5 / 梅花：敌方进入己方格减速 |

**rationale**：
- 上限提到 4 使「清一色」档位可达。
- 改为**手动打出**后，「什么时候兑现」本身成为一个决策（现在兑现换短期收益 vs 再攒一张换更强档位），且 3/4 张档位不再被「2 张自动触发」锁死。
- 「每格每社团只抽一次」堵死刷牌，同时产生一个副作用：**后期你只能靠抢新的花色格抽牌**，这与「抢地盘就是一切」支柱一致。

## 12. Roguelike 元素：校园传说

### PvP：公开 Draft

- 开局四家**同时**从**同一个 3 选 1 池**选择。**撞车不排他**（两家选同一条则两家都获得），避免出手顺序造成不公。

| 传说 | 效果 |
|---|---|
| 学霸 | 技能 CD -25% |
| 体育生 | 兵团移速 +15% |
| 班干部 | 同盟期共享视野，同盟时长 +15s |
| 后进生 | 占格最少时出兵 +30% |
| 转校生 | 开局额外获得一支 8 兵中立兵团 |

### PvE / 每日挑战：放开真随机

无公平性约束，允许真随机天赋 + 局内累积 build。

### 为什么不在 PvP 做局内 build

5-8 分钟塞不下 build 曲线，且局内累积会造成不可反制的滚雪球，与支柱 3、5 冲突。局内只保留两层：**开局传说 + 广播站分支**。

## 15. 技术架构

### 15.1 项目结构

TypeScript monorepo：`core`（规则，不依赖渲染/网络，20 tick/s 固定步长 + 定点整数运算）+ `client`（Three.js）+ `server`。

### 15.2 同步方案

服务端权威，10 Hz 快照 + 客户端插值。

- **指令即时回显**：拖拽派兵**立即**在客户端画出虚线与兵团轮廓，不等服务端。10 Hz 只用于校正。
- **带宽估算**：256 格 × 2B + 200 兵团 × 8B ≈ 2.1 KB/快照 × 10 Hz ≈ 21 KB/s per client。
- 录像回放：记录指令流即可（core 确定性的红利）。

### 15.3 联机功能 ★修订 B7

房间码、断线重连、AI 接管、准备倒计时、服务端校验反作弊。MVP 不做匹配系统。

**断线规则（消除 v0.2 的矛盾）**：

| 场景 | 格子归属 | 产出 |
|---|---|---|
| AI 接管（默认） | 保持 | **恢复正常** —— AI 就是替打，与真人无异 |
| 关闭接管的房间 | 保持 | **停止**，直到重连 |
| 重连后 | 保持 | 恢复 |

**rationale**：v0.2 同时写「AI 接管」和「停止产出」是矛盾的 —— 既然 AI 在替打，就没有理由让它少产兵。

## 附录 A：战斗模型闭式解推导

设 A 有 N_A 兵、攻击 atk_A、血量 hp_A；B 有 N_B、atk_B、hp_B。

锁定交换率（每 0.5s）：

```
rA = N_B · atk_B · k / hp_A
rB = N_A · atk_A · k / hp_B
```

B 先归零的条件（B 阵亡时 A 仍存活）：

```
N_B / rB  <  N_A / rA
N_B · hp_B / (N_A · atk_A · k)  <  N_A · hp_A / (N_B · atk_B · k)
N_B² · hp_B · atk_B  <  N_A² · hp_A · atk_A
```

即：

> **A 胜 ⇔ N_A² × atk_A × hp_A > N_B² × atk_B × hp_B**

A 的幸存兵力：

```
N_A − rA × (N_B / rB)
= N_A − (N_B · atk_B · k / hp_A) × (N_B · hp_B / (N_A · atk_A · k))
= N_A − N_B² · atk_B · hp_B / (N_A · atk_A · hp_A)
```

**三条推论**：

1. **等兵力（N_A = N_B）时退化为 atk × hp** —— v0.2 的说法只在此时成立。
2. **战斗结果对兵力是二次的**：40 打 20 强于两个 20 打 20。判据含 N²，故出兵速度以**平方**进入社团总强度 → 出现 6.2 的「出兵²×攻×血」口径。
3. **TTK（均匀对抗）= 0.5 / k 秒**，与兵力无关，只由 k 决定。故 k 是唯一需要调的战斗节奏旋钮，**不应通过调攻防血来控制战斗时长**（那会同步破坏社团平衡）。

**实现校验**：该闭式解可直接写成单元测试，模拟结果与公式误差应 < 1 个兵（定点数舍入范围内）。
